# Local Agent Harness | start-to-release plan

**Joining from the second PC? Start with [three copy-and-paste model prompts and GitHub setup](docs/FRIEND-PROMPTS.md).**
This is a planning baseline, not an implemented or approved release. Start with COORDINATION.md, MODELS.md and your file in handoffs/. Workstream directories are the ownership map.

## Target and boundaries
A local employee chat sends a goal over an access-controlled OS pipe to a policy broker. An embedded inference library reads pinned Gemma E2B weights from disk; there is no HTTP model server. The broker alone may execute schema-validated, allowlisted actions in a disposable headless guest with no network adapter, shared clipboard, host drives or employee desktop control. Browser fixtures load from local files; native app fixtures run inside the same guest. No remote websites, update checks, telemetry, license phone-home or localhost TCP services. Ship dependencies and signed model manifests on offline media; fail closed if unavailable. An enterprise workflow requiring a network is out of scope.

The default observation is a bounded accessibility/DOM tree (role, name, stable ID, state); redact secrets before inference or persistence. Treat app content as data, never authority. When targets are ambiguous ask the employee. Optional vision requires policy and explicit session permission, uses only a redacted guest region, never persists pixels by default. Local admin observation is separate, visible, opt-in and view-only; revocation closes the pipe. Recording starts only after informed employee consent for named apps, time and purpose. Show stop/pause, exclude passwords, discard unapproved drafts. Convert events to a versioned editable declarative skill: parameters, preconditions, target, bounded wait, action, verification and confirmation. Require review, dry run and approval before enablement; never generate executable scripts. Encrypt local saved data with per-user protection; expose retention and deletion controls. No employee data leaves the PC or enters development.

## Sequence and gates
1. **Kickoff — Astra + all:** inventory actual seats and employee reference hardware; choose supported Windows edition, virtualization prerequisites, RAM and disk ceilings. Obtain owner signoff on supported apps, consent copy and latency budget before timing runs. Run calibration; freeze schemas, risk register and synthetic fixtures.
2. **Feasibility — isolation + inference:** independently prove disconnected guest and embedded CPU inference, then join them for one local form. Measure cold load, p95 action latency, peak RAM and context limits. Unsupported hardware or missing rights blocks install; do not fall back to host control or cloud.
3. **Vertical slice — all six:** integrate chat → observation → proposal → validation → action → verification. Add native desktop fixture, explicit consequential-action confirmation, stop and timeout. Independent qualification owner verifies before broadening workflows.
4. **Feature complete — experience + skills:** ship role-separated settings, context budgets, speed presets, observer, recorder/editor, dry run, skill rollback, optional vision. Repeat gates below at minimum and maximum approved configurations.
5. **Offline candidate — qualification + Astra:** pin toolchain, dependencies, weights and guest image by digest; inventory licenses, generate SBOM, sign bundle, scan repository and history for secrets/non-synthetic artifacts. Exercise upgrade, uninstall and recovery on a clean disconnected reference machine. Publish no evidence containing employee records.
6. **Release decision:** independent reviewer attaches command, machine/configuration, fixture seed, expected/actual and pass/fail for every gate. Any critical privacy, isolation or offline failure blocks release. Owner approves a signed local candidate and rollback image. Only a later explicit instruction authorizes public publication to one new upstream, without forks. Support through manually imported signed updates; rollback on regression. No silent online support channel.

## Acceptance matrix (planned, not executed)
|Gate|Stimulus and required evidence|
|---|---|
|Offline lifecycle|Cold install, launch, chat, execute, observe, record, update and uninstall with NIC disabled. Trace product and child socket/DNS attempts as well as packets: zero network attempts including loopback. Missing/corrupt weights produce local error, no download.|
|Isolation|Run browser and native fixtures while employee types in host editor. Host focus/text unchanged; guest cannot see host sentinel, clipboard or another session. Destroy guest and verify session artifacts gone.|
|Grounding and vision|Structured-only task passes with zero screenshots; ambiguous target causes clarification and no click. With separate consent enable image-only fixture, revoke and verify capture stops.|
|Skill lifecycle|Refuse consent: no events/files. Grant scoped consent, enter synthetic secret, pause/resume, stop, edit selector/wait, dry run, approve and replay. Search artifacts for secret; none. Revoke mid-recording, crash/restart and delete; no automatic resume or retained unapproved recording.|
|Wait and pace|Inject ready delays of 0, 2 and 8 seconds plus never-ready at slow/fast pace. Act exactly once only after readiness; bounded timeout otherwise. Cancel while waiting and verify no later action.|
|Roles and observation|Employee cannot change admin settings; observer off by default. Local authorized view shows only guest with visible indicator, rejects input and terminates on revoke. Audit contains no field values.|
|Context and policy|Set two supported caps, reject out-of-range value, exhaust budget; reserve output and policy, compact or ask instead of dropping consent. Reject malformed actions, instructions inside fixture text and unconfirmed destructive actions.|
|Chat and reliability|Employee sees progress, clarification and final verified state; stop mid-task, restart and confirm no duplicate side effect. Run each supported fixture at least ten times; every state assertion must pass. Compare measured performance with signed kickoff budgets.|
|Distribution|Repeat clean install from signed media without developer tools. Reject tampered bundle; upgrade with existing approved skill, roll back and run it again. Uninstall removes application; verify documented keep/delete choice for user data.|
